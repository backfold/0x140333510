# 계층3 심층: 0x8e/0xbe 구조 + 타입 패밀리 (2026-10-18, 세션2)

도구: `scripts/py/inner-parse.js`~`inner-parse7.js`, `layer3-classify.js` (전체 분류표 → `logs/layer3-classify.txt`)

## 세션 프로파일 (사실)

- 로그인 핸드셰이크 = #1~#16 (0x0d hello → 0x3d/0x42/0x51 → 0x08 하트비트 → 0xbe/0xbc 채널목록).
- **#17~#83012 구간의 C2S는 단 1개 프레임**(0x08/6B). 클라이언트는 로그인 후 사실상 무송신 — 서버가 0x8e 등 상태 스트림을 일방 송신(로비 대기 상태).
- 0x8e: 총 54,092 중 53,670이 plen=198. 크기 변형: 46:106, 150:105, 166:28, 158:23, 238:20, 174:19, 110:13 등.

## 198B(LEN=208) 채움 구조 (사실 + 추론)

- **사실**: 플레인 계열 태그의 198B 페이로드는 [가변 헤드 영역(대략 오프셋 2~31 시작)][단주기(2~3B) 반복 패턴 채움 꼬리] 구조. 채움 패턴 예: `666666…`, `777777…`(0xd7/0xbd), `EEEE…`(0xc3/0xdd/0xde), `WWWW…`(0xd9), `TUUTUU…`(0xca 일부), `GFFGFF…`(0x88/0x8a), `RSSRSS…`(0x89/0x8b), `HIIHII…`(0x34/0x4b/0x54/0xac), `100100…`(0x8f), `4444…`(0xbc), `0000…`(0x8c).
- **사실**: 0xbe 상위 트리그램이 `30 30 30`('000')·`45 45 45`('EEE') 등 3연속 동일문자 — 채움 런이 지배적. P[i]==P[i+1] 59.6%(0 포함)/비제로 41.8%.
- **추론**: 대부분의 메시지가 가변 데이터(머리) + 태그 고정 채움으로 198B 고정 길이로 패딩됨. LEN=208 우세의 원인. (238B 초과 변형 존재 → 엄격 고정은 아님)

## 0x8e plen=198 세부 (사실)

- 트레일러 `c8 c8 01 49 7f` @193..197: 45,736/53,670(85%) 일치. byte192는 가변(0x00이 49%) — sum/xor/±0x25 체크섬 가설 전부 기각(각 22/1/374 히트 = 우연 수준).
- byte0 분포가 트레일러 유무로 이원화: 있음 그룹 `0x25:35916, 0x21, 0x15, 0x6b, 0x66…` / 없음 그룹 `0x2c:1615, 0x41, 0x34, 0x3f, 0x39…` → 두 하위 클래스.
- 몸통(2..191) 0 비율 46%, 비제로 인접동일 15.0% (무작위 기대 ~0.4%) — 반복 토큰 스트림(`0d 3d 37 37 37`, `5e 00 17 7f 01`, `02 02 30 00 7e 4e 04 04`, `59 00 17`, `04 04 54/57` 등). 상위 트리그램 `50 50 50`:41991, `02 02 30`:40977 …
- 비-198 변형(46/110/150/166/190B 등)은 **고엔트로피**: 8B 레코드 `[var8][0e b1][3B][92][3?][var8]` 반복, 레코드 간 상수부 동일·첫 바이트만 가변(#28: `00/4f/29 0e b1 2a 82 92 3c b9`) → 상태 비의존(무상태) 인코딩.

## 0xbe 레코드 스트림 (사실 + 가설)

- **사실**: 고정 템플릿 + 가변 필드 레코드 반복. #531: `^,g==00000440~''` + 가변 6자(`I70504`/`O10504`/`N99742`/`N33742`/`I70742`) ×5+, #513: `n44999999==w..` + 가변 6자(`G::>9?`/`@>9>9?`/`F89>9?`/`G0004=`), #303: `V#2w33222222k2%D32>?98;U55e` + 가변(`L237?:76`/`L1132031`).
- **사실**: 로그인 직후 #14는 부분 평문 — `-10;6713`, `(9,-1,+422`(좌표형), `F101:065` 등.
- **가설[미검증]**: 가변 필드 문자셋이 '0' 이상 연속(`:`=0x3a, `>`, `?` …) — 값>9를 확장 문자로 쓰는 십진 변형 또는 인쇄가능 문자 니블 인코딩일 가능성. #24 전체에 단일 XOR/±시프트는 무의미(원본 94% 인쇄가능, 변환 이득 없음).

## 미해결 갱신

- 0x8e/0xbe 페이로드의 의미 해석(레코드 스키마)은 클라이언트 파서 확보 전 불가 — 2단계 핸들러는 VM 전용(기존 결론, cipher-suite-map.md callsite census와 정합).
- inner `[u16le sublen]` 관측은 0x8e 프레임내 완결 파싱 실패(500프레임 중 bad=500, ok=323 메시지)로 **일반 규격으로는 기각** — 특정 프레임(LEN=208 최초 프레임 `03 00 ad dd…`)에만 해당하는 국소 구조로 강등.
